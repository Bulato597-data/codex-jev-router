# Global Jev Model Routing

For each **new actionable task that needs a model selection**, first refine the user's request into a concise execution brief. Preserve the requested scope and intent; do not silently add work. If the user is still discussing, correcting, or iterating the task, reflect material changes in the brief and route the latest agreed version before execution. Do not call Jev for ordinary conversation, acknowledgments, status questions, or a continuation that does not change the task or require a new model choice.

Send that approved brief once on standard input to `~/.local/bin/jev-route`, before inspecting files, researching, editing, or acting. Do not add a timed delay. Never send credentials, private keys, tokens, or task text containing secrets to Jev. A new automatic task launch should invoke Jev once regardless of the local keyword lane; explicit user-selected model/lane overrides do not need a Jev call.

Jev has no memory and evaluates only the task text in the current request. When routing a new phase of an ongoing goal, include the complete goal scope, current phase, milestones and dependencies. Do not rely on Jev to infer missing objectives from earlier turns, a goal label or duration. Ordinary unchanged continuations do not require another routing call.

Treat `jev.verified: true` as a valid TypeSafe Choice. `jev.choice` and `jev.effort` are Jev's advisory; `recommendation` is the final route after local safety floors. Pause only when that final route comes from an accepted, confidence-qualified Jev choice (`route.source == jev-choice`) and differs from the active desktop model or effort. If the active desktop model or effort cannot be established, treat that as needing manual confirmation and pause. In the pause reply, state exactly: Jev's model and effort, the final model and effort, model confidence, effort confidence when available, and any local override. Then make no task calls, file reads, research calls, edits, or implementation steps. Stop so the user can choose the displayed model and effort in the desktop picker and say “continue.” Resume only after that continuation. Never claim the active model changed automatically. When `jev.confidence_details` is present, report model confidence and reasoning-effort confidence separately. `jev.confidence` is the raw model Choice score. A qualified model choice can have an uncertain effort answer; `effort-confidence-floor` means a disclosed local effort setting applies, not that Jev supplied a confident effort. Model confidence below 0.70 still uses local model fallback.

Jev's recommendation is for the parent model and reasoning effort. Complete the existing routing handoff before starting the main task or choosing delegation; when a pause is required above, the user manually selects the displayed parent model and effort and says “continue” first.

Once execution resumes, the parent decides whether subagents are worthwhile and explicitly chooses each worker's model and reasoning effort. Assign smaller, well-defined tasks to suitable lighter models. Use stronger workers where complexity or risk warrants, including the same model as the parent when justified. Parallelize independent tasks when useful, avoiding duplicated work and conflicting edits. The parent remains responsible for integration, reviewing worker results, and final acceptance checks. Delegation does not change existing approval boundaries.

If Jev is not requested, unavailable, malformed, below the confidence floor, or otherwise unverified, continue under the local routing policy without asking the user to retry or switch models. The desktop default is `gpt-6-luna` at `xhigh`. Use the lightest available model and effort that safely meets the task's quality requirement; raise capability when scope, ambiguity, verification burden, or consequences materially require it.

This helper and its credential access are global to local Codex desktop and CLI chats on this Mac, across projects. A cloud ChatGPT Work runtime cannot access the Mac helper or Keychain. Do not claim Jev coverage in ChatGPT Work unless a separately authenticated remote bridge has been implemented and verified from that runtime.
